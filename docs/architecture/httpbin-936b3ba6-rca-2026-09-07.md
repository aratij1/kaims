# RCA: HighNetworkPacketLoss on httpbin-failure-lab

Incident: 936b3ba6-759f-4fb2-ba86-12954a2302ea

## Finding

The configured target is an intentional HTTP failure endpoint,
https://httpbin.org/status/503. The blackbox http_2xx module correctly rejects
its 503 response. The HighNetworkPacketLoss rule actually evaluates the
five-minute HTTP probe success ratio below 95% for five minutes. It does not
measure packet loss. Therefore this event is a deliberately unsuccessful HTTP
availability check admitted as an operational incident, with a misleading alert
name. Actual packet loss and customer/business impact have not been established.

## Direct evidence

Fresh paired probes on 7 September 2026 from the same exporter showed:

| Target | HTTP status | TLS | Probe result | Duration |
|---|---:|---:|---|---:|
| /status/503 | 503 | established | failed | 1.053 s |
| /status/200 | 200 | established | passed | 1.060 s |

DNS resolution and an HTTP response were also captured in the diagnostic logs.
This confirms working connectivity for those observations; it cannot exclude
intermittent network failures throughout the original incident window. An earlier
stored scrape reported HTTP status 0, so it is not evidence of a received 503.

Timestamped evidence: [probe observations](httpbin-936b3ba6-rca-evidence-2026-09-07.json).
Configuration: observability/prometheus.yml, observability/blackbox.yml,
observability/alert.rules.yml (HighNetworkPacketLoss).

## Why automation stopped

The persisted investigation is hypothesis/insufficient evidence, with a
human_requested requirement for distributed traces. Its blockers are
EVIDENCE_REQUIREMENTS_OPEN, RCA_NOT_GROUNDED and RESOLUTION_NOT_READY.
There is no execution or validation. Distributed traces from this external
service have not been provided; no instrumentation access is established.
The direct HTTP observation supports the diagnosis above without inventing
internal service traces or a causal customer-impact chain.

## Corrective action and disposition

The target has already been explicitly labelled event_mode=simulation and the
Prometheus configuration reloaded. The existing intake guard quarantines new
simulation notifications instead of creating real incidents/Jira issues. This
classification fix is not endpoint recovery. Historical records remain intact.

For this historical incident, the supported disposition is administrative closure
as intentional failure-lab/test signal, with this RCA attached, rather than a
technical recovery claim. No closure was performed as part of this RCA.

If a successful availability baseline is desired, configure an approved healthy
target and collect independent passing observations over the required window.
Do not count the separate /status/200 control probe as recovery of /status/503.

Follow-up: separate HTTP availability alerts from genuine network packet-loss
monitoring; avoid generic internal trace requirements for externally owned probes
unless an actual trace source is configured. These follow-ups are not implemented
by this report. This report is an operator RCA, not a newly published backend RCA
version; the application's evidence gates have not been bypassed.
